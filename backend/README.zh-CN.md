# 多刊投稿审稿后台：本地测试说明

这是独立于原有静态演示页面的开发版后台，仅供虚构数据测试。它尚未连接 SCIENTARA 网站，不能用于真实稿件，也不能开放到公网。

目前可测试：机构与多刊、期刊角色、逐稿分配编辑、编辑回避、独立审稿文件、审稿人利益冲突声明、作者投稿、审稿意见、编辑决定、作者修回和再次送审。原稿、修回稿、各轮意见和决定分别保留；审稿人进入新一轮需要再次受邀和接受。测试账户、稿件、意见和 PDF 保存在本地。后台界面支持英语和简体中文；原静态演示页面仍保留 12 种语言选择。

期刊协调员可查看本刊投稿题目并分配符合条件的编辑，协调员身份本身不会授予摘要、稿件文件和审稿意见访问权。只有获得该稿明确分配且本刊编辑角色仍有效的编辑才能处理稿件。作者、受邀审稿人或执行分配的协调员不能被分配为该稿编辑；协调员若兼任编辑，需由另一位符合条件的协调员为其分配。协调员不能管理本人投稿、本人参与审稿或已回避的稿件。编辑可主动回避，权限立即终止，由协调员安排其他独立编辑。历史分配与决定保留，不会自动撤销既往决定；其他潜在利益冲突仍需人工核查。

新增本地规则检查，可检查题目、摘要及测试文件是否存在，不使用 AI，也不判断科研质量。可选的 OpenAI 题目和摘要写作建议默认关闭，目前只完成模拟接口测试，尚未进行真实 API 联调；这不代表双方已有正式合作。

新增默认关闭的本地出版模拟：获分配的编辑开始制作后，协调员逐稿分配制作编辑。制作编辑可访问录用原稿和制作文件，但该角色本身不能查看保密审稿意见或审稿人身份。制作编辑准备公开元数据并单独上传虚构 PDF，提交作者确认当前元数据和校样后，制作编辑才能明确执行测试发表。修改元数据或上传新校样后需重新确认。任何能够连接服务器的人都可以访问已发表测试文章，因此只能使用虚构材料并绑定本机运行。

新增基础测试卷期：协调员可为各刊建立虚构卷、期和年份；制作编辑可在测试发表前为文章选择本刊尚未发布的期次，也可暂不选择期次。选择变更后须由提交作者重新确认。满足条件后，独立协调员可在本地发布测试期次目录。

新增按刊独立的本地网站设计：期刊网站管理员可填写虚构的网站显示名称、标题和介绍，选择森林绿、墨蓝或陶土红三套配色，以及经典或杂志两种布局；先保存草稿和预览，再明确发布本地测试版本。历史版本可恢复到草稿，需再次确认才会发布。该角色本身不授予稿件访问权。

新建期刊默认要求作者为每个稿件版本上传独立审稿 PDF，并由编辑人工核查后才能邀请审稿人。系统不会自动删除作者姓名或文档元数据，也不能保证完全匿名；作者和编辑都需要检查文件、题目和摘要。审稿人须声明无利益冲突才能接受任务；如后来发现冲突，可再次声明，编辑会在工作台看到提示。既往编辑决定不会因此自动撤销。

## 本地运行

安装 Python 3.10 至 3.14 后，在项目根目录依次运行：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
cd backend
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

Windows 如果提示找不到 `python3`，请改用 `python`；激活环境时使用 `.venv\Scripts\activate`。浏览器打开 <http://127.0.0.1:8000/>。`seed_demo` 会创建两个虚构测试期刊和八个测试账户，包括第一刊的作者、编辑协调员、编辑、审稿人、制作编辑、网站管理员、AI 管理员及第二刊编辑；随机密码只在终端显示一次，请妥善保存。作者提交后，使用协调员账号进入“管理编辑分配”，将稿件分配给测试编辑。测试投稿时需准备两份虚构 PDF，编辑需核查审稿文件后才能邀请审稿人。可使用不同浏览器会话分别登录各角色。重复执行会创建另一组测试数据，不会重置原账户。

创建管理员可运行 `python manage.py createsuperuser`，再访问 `/admin/` 管理测试期刊和角色。管理员不会仅因该身份获得工作台中的稿件访问权。

## 可选的本地测试发表

本功能默认关闭，仅用于虚构材料。启用前请确保服务器只绑定本机。在 `backend/` 目录执行：

```sh
IPS_LOCAL_PUBLICATION_ENABLED=1 python manage.py runserver 127.0.0.1:8000
```

Windows PowerShell 可先执行 `$env:IPS_LOCAL_PUBLICATION_ENABLED='1'`，再执行 `python manage.py runserver 127.0.0.1:8000`。关闭时停止服务器，取消该环境变量并重新启动。系统会给测试文章页面添加 `noindex` 标记，但它不是访问权限控制；能够连接服务器的人仍可访问测试发表的题目、作者、摘要和 PDF。请勿将开发服务器开放到互联网。

启用同一开关后，可用网站管理员账号在工作台进入“期刊网站设计”，为其有权限的期刊创建虚构网站草稿、选择配色和布局并预览。确认发布后，能连接本地测试服务器的人均可访问该版本；后续修改仍是草稿，需要另行发布才会显示。恢复历史版本也只会修改草稿。后台界面支持英语和简体中文，但网站正文目前仅支持手工填写的一套内容，不会自动翻译；图片上传、自定义 HTML、拖拽设计和自定义域名尚未实现。该功能不会部署到 SCIENTARA 或其他外部主机。

编辑对最新版本作出录用决定后，在投稿详情开始本地制作。协调员进入“管理编辑分配”，选择稿件，再进入“管理制作任务分配”，为该稿指定符合条件的制作编辑。制作编辑从自己的工作台进入任务，可以下载录用原稿，填写虚构的公开作者及元数据，并上传一份独立的虚构发表用 PDF。提交作者登录后下载当前校样、核对元数据并确认；获分配的制作编辑再次确认后才能测试发表。如果之后修改元数据或上传新校样，作者需要重新确认。系统保留测试校样并在确认、发表和下载时核验 SHA-256 摘要，但这不等于病毒扫描或人工内容审核。测试发表后页面不支持修改，更正、撤稿和删除流程尚未实现。

协调员可在协调工作台选择期刊的“管理测试卷期”，创建卷号、期号、年份和可选标题。当前原型不支持创建后编辑期次信息。制作编辑应在文章测试发表前选择本刊尚未发布的期次，或保留“在线优先、不选择期次”；期次选择包含在作者确认内容中，变更后必须重新确认。文章一旦测试发表，当前原型不能修改其期次，也不能再将已在线优先发表的测试文章编入某一期。文章发表后即能通过本地地址访问，不必等待整期发布。

测试期次至少包含一篇已测试发表的文章、没有尚未发表的已分配文章且已发表测试 PDF 完整时，才能由符合条件的协调员发布。该协调员不能是本期文章的提交作者、受邀审稿人或已回避的编辑／制作编辑；系统无法据此识别其他共同作者和所有潜在利益冲突，仍须人工核查。发布后的测试期次不能再加入文章，目录按文章测试发表时间排序；人工排序、页码、文章编号、期次修改和撤回功能尚未实现。

制作编辑须同时具有有效的本刊角色和该稿制作任务分配。作者、受邀审稿人、已对该稿回避的人员和执行分配的协调员均不能被分配。制作编辑可主动回避，回避后也不能处理该稿的编辑或协调工作；编辑回避后同样不能处理该稿制作。协调员移除制作分配后，系统会阻止后续访问制作工作台、录用原稿和私有校样，但无法撤回已开始的下载；若文章已经测试发表，能连接测试服务器的人仍可访问公开页面及 PDF。既往分配、决定和作者确认仍保留。同一人如兼任编辑与制作编辑，须分别获得两项分配。其他潜在利益冲突仍需人工核查。

这里的确认仅代表提交账户，不代表所有共同作者、编辑或权利人已同意。该模拟尚无校样批注、完整卷期编辑与排期、许可管理、DOI 注册、索引或正式发表功能，不能用于真实稿件。

## 本地期刊 AI 策略

期刊 AI 管理员可从工作台进入“期刊 AI 策略”，配置现有题目与摘要建议任务是否启用、提交作者和获分配编辑是否可以请求，并设置本刊每 24 小时请求上限（1—100 次）。策略初始关闭，管理员必须明确设置。期刊管理员还需在 `/admin/` 的测试期刊中独立启用 OpenAI 元数据建议；服务端配置、提交作者针对具体元数据的授权和每次请求确认也仍然必需。AI 管理员角色本身不授予稿件、摘要或审稿意见访问权。策略历史记录配置和操作者，不保存稿件正文或密钥。

每本期刊分别统计最近 24 小时的请求尝试，包括失败与取消；每个账户 24 小时最多三次的限制继续生效。确认页面会绑定策略版本；发送前策略发生变化时请求会取消，已经发出的请求无法撤回。既有结果在请求者仍有稿件访问权限时保留可见。该原型不提供正式账单或金额预算控制，SQLite 也不能保证生产环境中的并发额度控制。目前策略只控制现有 OpenAI 元数据任务，尚未接入 AI 网页设计或其他模型供应商。

本地任务分发层只接受已注册的元数据任务、OpenAI 及题目和摘要这两个字段；未注册的任务、供应商和额外字段会被拒绝。分发层本身不替代授权：调用工作流仍须先检查期刊策略、身份、作者授权、次数和请求确认。新增任务或供应商需要分别实现、检查权限并测试。

## 可选 OpenAI 测试

仅在隔离环境使用虚构数据时，管理员可在服务端设置 `IPS_OPENAI_ENABLED=1`、`IPS_OPENAI_MODEL` 和 `OPENAI_API_KEY`，并在测试期刊设置中启用 OpenAI 建议，同时由期刊 AI 管理员配置并启用本刊 AI 策略。密钥只应安全地设置在服务端环境中，不要写入代码仓库、浏览器或聊天。作者需针对具体版本、题目、摘要和任务用途授权；每次请求还需操作者确认。题目、摘要、版本或任务用途变化后需要重新授权。

请求只发送题目和摘要，不单独发送 PDF、作者账户字段或审稿记录；但如果题目或摘要本身包含个人信息，这些信息仍会被发送。API 可能收费，服务商可能保留数据；`store: false` 不等于零保留，具体以 [OpenAI 数据控制说明](https://developers.openai.com/api/docs/guides/your-data)为准。撤销授权会阻止后续请求，但不能撤回已发送的数据或正在进行的请求；此前结果仍保存在本地测试数据库。每个账户在本地测试环境 24 小时内最多发起三次外部请求，失败不会自动重试。

AI 输出仅供人工审阅，不会自动修改稿件或作出录用、拒稿决定。系统检查引用片段是否确实出现在题目或摘要中，但这不能证明建议正确，也不能保证模型忽略文中恶意指令。真实稿件不得使用当前测试版。

从旧版本地后台升级时，数据库迁移会保留测试稿件的文件路径与审稿分配。已有期刊和投稿沿用原有审稿文件策略；修改期刊策略只影响新投稿。旧任务如果没有利益冲突声明，会显示为“尚未声明”，审稿人须主动声明后才能继续下载或提交意见；未声明的已完成意见暂不计入录用或修回决定。新增迁移不会猜测旧稿件的编辑或制作分配：升级后需要由管理员授予相应的期刊角色，再由协调员逐稿分配；已有制作草稿也需要重新明确分配制作编辑。已有文章不会自动分配期次或发布期次；未变更的原有作者确认仍保留。已有账户不会自动获得网站管理员角色，也不会自动建立期刊网站。迁移 0010 不会自动创建 AI 策略或授予 AI 管理员角色；即使旧版 AI 开关已启用，也须明确配置新策略才能继续测试。迁移不可直接回滚，升级前应备份测试数据库和文件；如需返回旧版，请恢复备份。

## 当前限制

后台尚未实现自动匿名化、身份核验、完整利益冲突管理、可配置编辑规则、正式发表、邮件、DOI、可用于正式业务的 AI 治理、病毒扫描、备份恢复、多因素认证及生产环境安全配置。目前原稿 PDF、审稿 PDF 和作者回复支持版本记录，投稿题目、摘要及其他附件还没有版本管理。审稿人在接受邀请前可看到标题和摘要；系统不保证文件或摘要已匿名。作者在账户及期刊有效时仍可查看自己的投稿；审稿人须保有有效的本刊审稿角色。

编辑可以填写会展示给作者的决定说明。系统不会自动向作者公开审稿人身份或保密意见，但编辑仍需核对说明内容，避免手动带入保密信息。录用和修回决定需要至少一份已声明无利益冲突的审稿意见，初筛拒稿可以不送审。

请只使用虚构数据。用于真实稿件之前，还须完成安全设计、文件隔离与扫描、加密、正式数据库、权限和并发测试、备份恢复及业务验收。完整说明见 [英文文档](README.md)。
